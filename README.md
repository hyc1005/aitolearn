# 智慧学伴教师工作台

Windows 原生应用。前端使用 React、Ant Design 和 ECharts。后端使用 FastAPI、SQLite FTS5、PaddleOCR 和 smolagents。业务文件和数据库位于本机 `var/`。

## 安装与启动

安装 Python 3.11 x64 和 Node.js 22 或以上（含 npm）。以 PowerShell 从项目根目录运行。

    .\scripts\setup.ps1
    .\scripts\start.ps1

打开 http://127.0.0.1:8765。执行 `scripts/stop.ps1` 停止。遇到问题运行 `scripts/doctor.ps1`，查看 `var/api-error.log` 和 `var/worker-error.log`。处理旧版 DOC 需安装 LibreOffice，可通过 `SOFFICE` 指定可执行文件。完整安装时，安装脚本会在处理第一份 OCR 文件前准备 PaddleOCR 模型。

可用 `setup.ps1 -Python C:\path\python.exe` 指定解释器。仅验证数字 PDF、表格和 UI 时用 `setup.ps1 -SkipOcr -KeywordOnly`，并以 `start.ps1 -KeywordOnly` 启动。Windows x64 的 Python 3.12 关键词模式使用验收时固定的依赖版本。混合检索需要完整安装和首次向量模型下载。

## 首页与七个入口

根地址与首页按钮都进入**学情对话**。左侧固定七项：

| 入口 | 老师在这里完成什么 |
|---|---|
| **学情对话** | 默认首页。自由提问、上传文件、查询学情、确认并跟踪任务。 |
| **数据导入** | 选择文件、启动清洗、处理异常、核对并确认本批数据。页面内显示当前步骤与下一步按钮。 |
| **课程与资料** | 查看导入得到的课程指标，补充、校对和发布教材。该步骤可跳过。 |
| **班级诊断** | 从班级和测验出发，用指标矩阵找出值得关注的问题，继续查看学生分布。 |
| **画像** | 搜索学生或班级，通过雷达图和指标对照打开原始作答。 |
| **学习建议** | 查看和修订生成的建议、练习及审核结果，导出已确认成果。 |
| **设置** | 第一项是完整模型配置，其后是后台任务、运行环境和重新打开使用引导。 |

原 `#models` 定位到「设置 → 模型接入」。原 `#agent` 与 `#agent/<运行编号>` 继续打开任务记录或对应运行详情。桌面可收成图标栏，手机默认收起导航。各页标题旁不再放通用 JSON、CSV 按钮；异常导出在清洗报告，正式成果导出在学习建议。

## 学情对话

打开就能问。学生、班级和测验放在「添加上下文」中，只影响后续消息；历史回答保留当时的对象和快照。输入“看看 DC02 最近一次测验”时，后端从已确认快照解析对象和测验，并直接读取画像接口返回指标、覆盖人数和作答入口；匹配到多个对象时，在消息内列出候选项。

- 普通问题由当前模型回答，相关时引用已发布资料或已评分作答，并沿用服务器原文核验。
- 数据卡按已确认快照用 SQLite 汇总，不让模型推算成绩。试问「D01 去括号有进步吗？」可看到每次测验的得分率、已评分题数、前后变化和原始作答；再问「教材怎么讲这个知识点？」可打开已发布资料的片段和出处。两类问题也可以一起问。
- 首版对话任务包括：选择本机文件并启动导入清洗、查看清洗计数/异常/复核状态并确认本批数据、按班级/学生/某条作答生成学习建议并进入审核。
- 上传、清洗、待确认、生成、终审、完成和失败均取自后端。失败消息保留原问题、文件名或任务编号，并提供重试入口。
- 对话和关联任务写入本地 SQLite。刷新页面后恢复历史；已提交的后台任务继续执行，可从卡片的「打开任务」重新查看。
- 提案由后端校验对象、批次和快照后生成编号；重复确认返回同一结果。快照变化时展示变化并允许按新快照重新确认。

## 使用引导

首页的「第一次使用」卡片读取实际业务状态，每次只突出当前最有用的一步：空库导入第一批数据、清洗中查看进度、待确认核对数据、已有确认数据查看班级薄弱项、已查看作答生成建议、建议已生成进入审核。卡片支持「稍后」（本次会话隐藏）、「已了解」（跨刷新记忆）；设置中可重新打开。首次流程完成后自动收起。需要模型的步骤在未配置密钥时提供「前往设置」。

## 完整工作流

1. 在**数据导入**选择赛题 XLSX 或五张业务 CSV，点击「运行 Agent 清洗」。Python 结果与模型复核会显示真实计数（公开赛题基准为 806 行原始作答、799 个事件、790 个已评分状态、785 条有效已评分、5 条异常）。核对后确认并启用快照。
2. 在**课程与资料**整理已导入题库并发布；需要课标或教材时上传 PDF/Word/照片，检查解析和原文位置后发布。此步骤可跳过。
3. 在**班级诊断**按课程顺序、班级差异或覆盖查看矩阵，点指标查看测验观测和班级分布，再打开学生作答。
4. 在**画像**搜索 D01 等学生或班级，查看雷达图和指标覆盖，从指标打开原始作答；也可从作答发起学习建议。
5. 在**学习建议**打开草稿，修订教学说明、练习提示、顺序或给学生的话，保存后重新终审。通过后确认并预览学生练习单。页内「导出已确认成果」仅纳入当前快照、终审通过且教师确认的建议。

各项得分率只采用通过关联及分数校验的已评分记录。学生轴按有效得分除以满分统计，班级轴是个人得分率均值。画像和运维可在模型不可用时继续使用。

## 从附件到学习建议

聊天输入区的「＋ 添加 → 上传文件」默认自动处理：选中文件后，服务端验证格式和表结构，Agent 只对已验证的分组发起清洗或解析工具调用（模型不可用时按相同规则分流），并将任务状态写回会话。无法识别的文件不会提交。自定义表头可切换到手动预检，核对映射后再导入；仅本轮参考模式只发送可预览摘录，不入资料库。自动处理不会启用快照或发布资料，仍需教师确认。

「上传的教学资料」与从学情「题目与材料」表手动整理出的题库摘录分开显示。PDF 优先提取文字层，扫描页和图片才需要 PaddleOCR；资料详情会标明是否实际调用 OCR。未安装 OCR 时，纯文字 PDF 仍可解析，扫描件会明确提示需要配置 OCR。

提交学情时可指定一个学生或班级，在教师确认快照后自动启动建议任务。也可在「学习建议 → 新建建议」单独发起。「任务中心」按阶段显示清洗、解析、解读、草稿和终审；重试与诊断在对应任务里。成功的模型调用和等待中的阶段有整体耗时，对话的「执行过程与依据」只显示可核实的工具操作和引用，不展示原始内部推理。

## 模型接入

「设置 → 模型接入」预设 OpenCode Go（`glm-5.3-flash`）和 DeepSeek（`deepseek-flash`），也可添加自定义 OpenAI 兼容 API。保存连接后刷新目录，可搜索、勾选多个模型并指定新会话默认模型。若平台没有目录接口，手动登记模型 ID 即可。用平台默认档测试通过后，聊天菜单才列出该模型；自定义模型可另行登记并逐档测试 `reasoning_effort` 或 `thinking` 开关。聊天页切换模型和思考强度只影响下一轮，历史回答仍显示当时实际调用的模型。后台清洗和建议生成使用「后台默认平台」，不跟随聊天菜单。

密钥保存在本机凭据库，不写入 SQLite、响应、日志或 Git。自定义地址默认用 HTTPS，显式回环地址可用 HTTP；改地址须重新输入密钥。预设仍支持 `OPENCODE_GO_API_KEY`、`DEEPSEEK_API_KEY`（环境变量优先），以及已有的 `goapi.txt`、`OPENCODE_GO_BASE_URL` 和 `OPENCODE_GO_MODEL`。运行 `.\.venv\Scripts\python.exe -m scripts.check_model` 可验证后台平台的工具调用。

## 快照与资料索引

启动时按快照编号回填已确认历史数据，逐份校对作答数、已评分数和得分合计；重复启动不会重复计分。确认新快照时，写入查询表和切换活动快照在同一事务完成。学生画像可查看待评分、未作答和已评分记录（含零分）；已布置建议的练后回看保留原建议修订版及对应的基线快照。

已发布资料使用持久化 FTS5 索引；无可用向量服务时仍可按关键词检索。换版后普通搜索只查当前发布版本，已保存的旧引用仍能打开原来的版本和页码。有文本但没有页面预览的资料，会直接显示被引用的原文。

## 数据清理

先盘点，再按清单清理。脚本只处理项目根目录内的业务数据与衍生文件，不删除源码、`ori_data`、`.venv`、`node_modules` 或 `var/` 中的浏览器测试与依赖目录。

    .\.venv\Scripts\python.exe scripts/data_inventory.py --counts
    .\.venv\Scripts\python.exe scripts/clear_data.py --apply

盘点会列出数据库、上传/预览文件、清洗与索引产物、日志、截图、录屏和导出物的绝对路径。清理会清空数据库记录、移除历史验收副本与衍生文件，并在 `var/delivery/` 保留不含密钥的清理摘要。密钥仍保留在系统凭据库、环境变量或原有密钥文件中。

## 本机验证

    .\.venv\Scripts\python.exe -m unittest discover -s tests -v
    npm.cmd --prefix frontend run build

当前离线清洗工具可传入单个 XLSX、单个 CSV 或 CSV 目录，产物包含业务表、报告、异常、全部原始行位置及版本清单。

    .\.venv\Scripts\python.exe -m scripts.clean_data --input path\to\workbook.xlsx --output var\cleaning-check

开发前端热更新使用 `npm.cmd --prefix frontend run dev`，API 由 Vite 代理。OpenAPI 位于 `/docs`。

## 关键位置

- `frontend/src/main.tsx`、`frontend/src/LearningChat.tsx` 和 `frontend/src/style.css` 实现七项导航、对话首页、结果卡与引导。
- `backend/conversation.py` 负责对话会话、对象解析、结果卡、提案和引导状态；`backend/main.py` 与 `backend/jobs.py` 负责 API 与后台任务。
- `backend/data.py`、`backend/snapshots.py`、`backend/agent.py` 负责清洗、画像与建议；`backend/materials.py`、`backend/search.py`、`ocr_worker/` 负责资料解析和检索。
- `tests/test_data.py`、`tests/test_workflow.py` 包含数据清洗、工作流、对话、提案和引导回归。
- `scripts/data_inventory.py`、`scripts/clear_data.py` 负责交付前的盘点与清理。
